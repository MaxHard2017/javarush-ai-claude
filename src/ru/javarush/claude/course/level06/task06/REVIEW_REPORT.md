# Отчёт ревью: «Змейка»

## Обзор

Браузерная «Змейка» на чистом JavaScript и Canvas (`game/index.html`): поле 20×20, шаг движения — 120 мс через `setInterval`. Проверка ограничена пунктами из `REVIEW_BRIEF.md`; базовые механику движения/роста и утверждённый визуальный стиль не оцениваю.

## Находки

1. **[medium] Быстрые повороты могут теряться или перезаписывать друг друга.**
   - **Место:** `game/index.html`, обработчик `keydown` (строки 144–153); применение направления — `moveSnake()` (строка 89).
   - **Что не так:** проверка разворота сравнивает новое направление с `dir`, которое меняется только на игровом тике, а не с уже поставленным в очередь `nextDir`. Например, при движении вправо быстрый ввод «вверх, влево» до следующего тика отклоняет «влево» как разворот назад относительно старого направления. Ввод «вверх, вниз» за тот же промежуток, наоборот, перезаписывает ожидающий поворот на «вниз».
   - **Улучшение:** валидировать ввод относительно ожидаемого направления и обрабатывать не более одного поворота на тик (или использовать небольшую очередь поворотов с запретом разворота относительно последнего принятого направления). Это сделает быстрые повороты предсказуемее.

2. **[medium] Столкновение с уходящим хвостом может завершить игру ошибочно.**
   - **Место:** `game/index.html`, `checkCollision()` (строки 102–113) и `tick()` (строки 130–140).
   - **Что не так:** после добавления новой головы `checkCollision()` проверяет её против всех сегментов, включая последний сегмент старого хвоста. Сам хвост удаляется только после проверки. Поэтому на ходе без роста попытка войти в клетку, которую хвост освобождает в тот же тик, считается столкновением.
   - **Улучшение:** при проверке столкновения на ходе без роста не учитывать уходящий последний сегмент; при росте продолжать учитывать всё тело.

3. **[low] Стрелки могут прокручивать страницу вместо управления игрой.**
   - **Место:** `game/index.html`, обработчик `keydown` (строки 144–153).
   - **Что не так:** событие для клавиш со стрелками не отменяет действие браузера по умолчанию. На странице, которая прокручивается (например, на невысоком экране), нажатие стрелки может одновременно с поворотом змейки сдвинуть страницу.
   - **Улучшение:** вызывать `preventDefault()` только для распознанных клавиш управления.

4. **[low] На старте не показана подсказка по управлению.**
   - **Место:** `game/index.html`, начальная разметка `<body>` (строки 43–50).
   - **Что не так:** видны название, счёт и поле, но игроку не сообщается, что змейка управляется стрелками.
   - **Улучшение:** добавить короткую подсказку рядом со счётом или полем, например «Управление: стрелки».

## Что работает хорошо

- Проверка границ поля явно ловит выход головы за стены в `checkCollision()`.
- Проверка тела отделена в `checkCollision()`, а завершение игры останавливает таймер в `tick()`.
- Игровой цикл прост и читаем: движение, столкновение, удаление хвоста, отрисовка.

## Ограничение проверки

Это статический разбор кода. Игру в браузере и поведение на разных размерах окна вручную не запускал; находки о вводе и столкновении следуют из порядка операций в коде.
