# ТЗ: публикация статической страницы

## 1. Суть задачи

Опубликовать страницу `index.html` из текущего проекта в интернете, чтобы любой человек мог открыть её по публичной HTTPS-ссылке без запуска локального сервера. Целевой сервис — **Netlify на бесплатном тарифе**, способ публикации — Netlify Drop; база данных, серверная логика и сборка не используются.

Результат работы: открывающийся адрес вида `https://<имя-сайта>.netlify.app/`, на котором отображается содержимое текущего `index.html`.

## 2. Точные требования

### 2.1. Исходные файлы

- Главный файл страницы: `index.html`.
- `index.html` должен лежать в корне загружаемой папки.
- Для публикации используется папка `task01`, содержащая `index.html`.
- Внешние файлы, подключённые относительными путями, если они появятся, должны находиться внутри этой же папки.
- Страница должна открываться как статический HTML-файл; серверная обработка не требуется.

### 2.2. Требования к хостингу

- Сервис: Netlify.
- Тариф: бесплатный; переход на платный тариф и добавление платёжных данных запрещены.
- Способ загрузки: Netlify Drop через веб-браузер, без установки CLI и без настройки собственного сервера.
- Публичный адрес: HTTPS-адрес на домене `netlify.app`.
- Посетитель должен открывать страницу без входа в аккаунт Netlify.
- При открытии корневого адреса `/` сервис должен отдавать `index.html`.
- Ссылка должна быть доступна с другого устройства и из отдельной сети после завершения публикации.
- В проект нельзя добавлять базу данных, API, серверный код, переменные окружения, секреты, авторизацию или платёжные функции.

### 2.3. Требования к публикации

1. Открыть страницу Netlify Drop в браузере.
2. Перетащить в область загрузки папку `task01` целиком, а не один файл `index.html`.
3. Дождаться сообщения об успешном создании сайта.
4. Скопировать выданный публичный HTTPS-адрес.
5. Открыть адрес в новой вкладке без предварительного открытия локального файла.
6. Проверить страницу в обычном окне браузера и в приватном окне.
7. Проверить тот же адрес на телефоне или другом устройстве.

Публикация считается выполненной только после проверки адреса вне локальной файловой системы.

### 2.4. Содержимое опубликованной страницы

Хостинг не должен менять внешний вид и содержимое исходной страницы. По публичному адресу должны быть видны:

- заголовок `Магазин чудес`;
- ссылки `Каталог` и `Заказать`;
- заголовок `Всё для дома и хобби в одном месте`;
- три товара каталога;
- раздел `Оформить заказ`;
- подпись `© Магазин чудес. Уют и хобби с доставкой.`

## 3. 🔴 Граничные случаи

- **Пустая папка:** не загружать её; сначала добавить в корень `index.html`. Пустой деплой не считается успешным.
- **Файл отсутствует:** если в корне нет `index.html`, публикацию остановить и исправить структуру папки.
- **Неправильный уровень вложенности:** папка вида `task01/task01/index.html` запрещена. Файл должен находиться по пути `task01/index.html`.
- **Регистр имени:** `INDEX.html` и `Index.html` не заменяют `index.html`; имя должно быть написано строчными буквами.
- **Один файл вместо папки:** загрузка отдельного `index.html` запрещена, поскольку относительные файлы и структура проекта могут потеряться.
- **Лишние файлы:** файлы, не нужные странице, не загружать. В текущем варианте достаточно папки с `index.html`.
- **Повторная загрузка:** повторная публикация той же версии не создаёт новое требование к странице; проверяется последний успешно опубликованный вариант.
- **Изменение после публикации:** локальные правки не меняют уже опубликованную страницу. После изменения `index.html` папку нужно загрузить заново и повторить весь чек-лист.
- **Неразрешённый адрес:** если публичная ссылка возвращает `404`, проверить, что `index.html` лежит в корне загруженной папки, затем выполнить повторный деплой.
- **Ошибка загрузки:** не считать страницу опубликованной по одному факту выбора папки. Нужны сообщение об успехе и открытие публичной ссылки.
- **Сетевой сбой:** при обрыве соединения во время загрузки повторить загрузку после восстановления сети; неполная загрузка не принимается.
- **Обновление страницы:** после открытия публичного адреса клавиша перезагрузки не должна вести на `404`.
- **Прямые якорные ссылки:** адреса `/<путь>#catalog` и `/<путь>#order` должны открывать ту же страницу и прокручивать её к соответствующему разделу.
- **Открытие локального файла:** адрес, начинающийся с `file://`, не является доказательством публикации и в проверку не засчитывается.
- **Приватность:** в загружаемой папке не должно быть паролей, токенов, ключей и личных файлов; всё содержимое публичного деплоя доступно посетителям.

## 4. Управление и ввод

- Единственное действие при публикации — перетаскивание папки `task01` в область Netlify Drop.
- Во время загрузки не закрывать вкладку и не выбирать другую папку.
- Кнопки `Смотреть каталог` и `Заказать` относятся к содержимому исходной страницы. В рамках этой задачи их поведение не разрабатывается и не изменяется.
- Команды терминала, локальная база данных и интерактивная настройка сервера не используются.

## 5. Внешний вид и адаптация

Хостинг должен отдавать страницу без изменений CSS и HTML. В опубликованном варианте сохраняются значения исходного файла, включая:

- фон страницы `#9a9a9a`;
- фон шапки `#7d7d7d`;
- фон карточек `#b0b0b0`;
- цвет границы карточек `#666`;
- системный шрифт `Times, serif`;
- горизонтальный viewport через `<meta name="viewport" content="width=device-width, initial-scale=1">`.

Страница должна помещаться в ширину экрана телефона без горизонтальной прокрутки. Хостинг не добавляет изображения, шрифты, CSS-фреймворки и JavaScript.

## 6. Состояния

### 6.1. Страница опубликована

Публичный HTTPS-адрес открывается, в заголовке вкладки отображается `Магазин чудес`, а на странице присутствуют все элементы из раздела 2.4.

### 6.2. Загрузка выполняется

До сообщения об успешном деплое адрес не передавать другим людям и не считать рабочим. Вкладку Netlify Drop не закрывать.

### 6.3. Ошибка публикации

Если сервис показывает ошибку или адрес не открывается, результат не принимается. Нужно проверить структуру папки, отсутствие секретов и состояние сети, после чего повторить загрузку.

### 6.4. Страница не найдена

Ответ `404` означает, что публичная ссылка не прошла проверку. Исправить расположение `index.html` в корне папки и опубликовать папку заново.

### 6.5. Нет сети у посетителя

При отсутствии интернет-соединения публичная страница недоступна; это ограничение статического хостинга, а не дефект HTML. При восстановлении сети адрес должен открыться снова.

## 7. 🚫 Не входит в задачу

- регистрация собственного домена;
- подключение базы данных;
- серверная часть и API;
- формы с отправкой данных на сервер;
- авторизация пользователей;
- платежи и корзина магазина;
- автоматический деплой через GitHub Actions или CI/CD;
- установка Netlify CLI;
- изменение дизайна или логики `index.html`;
- добавление аналитики, рекламы и сторонних виджетов;
- настройка резервного копирования;
- гарантия доступности при отсутствии интернет-соединения;
- публикация секретов или личных файлов.

## 8. Порядок выполнения

1. Проверить, что файл называется `index.html` и лежит непосредственно в папке `task01`.
2. Удалить из загружаемой папки файлы, не относящиеся к странице и не предназначенные для публикации.
3. Открыть Netlify Drop и выбрать бесплатный способ размещения.
4. Загрузить папку `task01` целиком.
5. Дождаться успешного завершения деплоя и получить HTTPS-ссылку.
6. Открыть ссылку в новой вкладке, затем в приватном окне.
7. Проверить страницу с телефона или другого устройства.
8. Проверить наличие текста, карточек, якорей и отсутствие горизонтальной прокрутки.
9. Зафиксировать рабочую ссылку как результат задания.

## 9. Анти-паттерны

- Не открывать страницу через `file://` и не выдавать это за публичный хостинг.
- Не загружать один `index.html`, если публикация ожидает папку проекта.
- Не класть `index.html` во второй вложенный каталог.
- Не подключать базу данных или сервер ради страницы, которая состоит из статических файлов.
- Не использовать платный тариф для выполнения задания.
- Не считать URL рабочим до проверки в новом окне и на другом устройстве.
- Не хранить в публичной папке ключи, токены, пароли и личные документы.
- Не менять исходный HTML/CSS в рамках задачи о хостинге.
- Не добавлять ручные серверные настройки, которые не нужны Netlify Drop.

## 10. Критерии готовности

- [ ] В папке публикации существует файл `task01/index.html` с именем в точности `index.html`.
- [ ] Использован Netlify на бесплатном тарифе без платёжных данных.
- [ ] Папка `task01` загружена целиком через Netlify Drop.
- [ ] Получена публичная ссылка с HTTPS и доменом `netlify.app`.
- [ ] Ссылка открывается в новом обычном окне браузера без входа в Netlify.
- [ ] Вкладка страницы содержит заголовок `Магазин чудес`.
- [ ] На странице видны шапка, две навигационные ссылки, герой-блок, три товара, раздел заказа и подвал.
- [ ] Перезагрузка публичного адреса не приводит к `404`.
- [ ] Переходы к `#catalog` и `#order` работают на публичной ссылке.
- [ ] Страница открывается в приватном окне браузера.
- [ ] Страница открывается на телефоне или втором устройстве.
- [ ] На ширине телефона нет горизонтальной прокрутки.
- [ ] Локальный адрес `file://` не использован как доказательство готовности.
- [ ] В публичной папке нет паролей, токенов, ключей и личных файлов.
- [ ] После изменения исходного файла повторная загрузка и проверка выполняются заново.
