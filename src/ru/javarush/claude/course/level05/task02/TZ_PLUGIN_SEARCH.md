# ТЗ: поиск плагина для визуальной доводки веб-страницы

## 1. Суть задачи

Найти, установить и применить **плагин как набор взаимосвязанных skills**, который умеет доводить существующую веб-страницу: выравнивать вёрстку, приводить к единой системе типографику и отступы, а также устранять противоречия в визуальном стиле. Результатом должна быть та же страница с сохранённой логикой и контентом, но с проверяемой визуальной цельностью на широком и узком экране.

Стек проверки: локальный проект с существующей HTML-страницей и её CSS/JS, Claude Code plugin package со skills, локальный браузер для визуальной проверки. Новый сайт и новый skill в рамках задачи не создаются.

## 2. Входные данные и результат

### Входные данные

1. Существующая страница проекта: `TARGET_PAGE`, включая подключённые CSS, JS и локальные изображения.
2. Рабочая копия проекта, которую разрешено изменять.
3. Каталог или репозиторий, из которого можно установить plugin package.
4. Снимок исходного состояния страницы:
   - скриншот при ширине `1440 px`;
   - скриншот при ширине `390 px`;
   - список интерактивных элементов и их исходное поведение.

Если `TARGET_PAGE` не задан или страница не открывается до начала работ, поиск считается заблокированным: нельзя выбирать произвольный файл вместо неё.

### Интерпретация свободной формулировки

Входной запрос может быть сформулирован бытовыми словами: «сделай красиво», «причеши страницу» или «сделай аккуратнее». Наличие слова `красиво` не является причиной для отказа и не считается готовым критерием качества. Плагин обязан преобразовать такую формулировку в таблицу «запрос → проверяемый признак» до внесения правок:

| Формулировка пользователя | Проверяемый признак |
|---|---|
| «сделай красиво» | выполнены числовые правила типографики, отступов, сетки, цветов, радиусов и контраста из раздела 4 |
| «причеши вёрстку» | контейнеры и повторяющиеся блоки выровнены, переполнение отсутствует на ширинах из раздела 8 |
| «сделай стиль цельным» | одинаковые роли компонентов используют общие токены и одинаковые состояния |

Если после разбора остаётся несколько допустимых трактовок, плагин выбирает критерии, уже заданные в этом ТЗ, и фиксирует это в отчёте; он не задаёт результат через субъективную оценку и не меняет контент ради внешнего вида.

### Результат

1. Один выбранный и установленный plugin package с зафиксированными названием, источником и версией.
2. Отчёт о составе плагина: список входящих skills и роль каждого в общем процессе.
3. Изменённая `TARGET_PAGE` с сохранёнными контентом, ссылками и поведением.
4. Сравнение «до/после» при ширине `1440 px` и `390 px`.
5. Отчёт проверки с командами, скриншотами, перечнем изменённых файлов и результатами чек-листа из раздела 10.

## 3. Что считается плагином, а что не подходит

Кандидат допускается к проверке только при выполнении всех условий:

- это устанавливаемый plugin package, а не отдельный файл `SKILL.md`;
- пакет содержит не менее `3` отдельных skills, каждый с собственной задачей и инструкциями;
- в пакете есть манифест с названием и версией, а установка описана воспроизводимой командой;
- skills образуют один рабочий процесс: аудит страницы → план изменений → внесение правок → проверка результата;
- пакет умеет работать с уже существующим кодом, а не только генерировать страницу с пустого листа;
- применение пакета приводит к изменениям файлов проекта или к обоснованному отчёту «изменения не требуются» после аудита;
- пакет не требует смены фреймворка, языка, сборщика или дизайн-системы проекта.

Кандидат отклоняется, если он представляет собой один универсальный skill, коллекцию несвязанных советов, только галерею шаблонов, только генератор макетов или инструкцию без возможности применить её к локальной странице.

## 4. Обязательные возможности плагина

Плагин должен закрывать все четыре обязательные области. Отсутствие любой области означает отклонение кандидата.

### 4.1. Аудит существующей вёрстки

Перед правками плагин обязан:

- найти точку входа страницы и связанные стили;
- определить основные секции, контейнеры, повторяющиеся компоненты и интерактивные элементы;
- перечислить обнаруженные проблемы, а не сразу переписывать страницу;
- зафиксировать, какие части нельзя менять: текст, ссылки, JS-логику, публичные действия кнопок.

### 4.2. Типографика

После применения должны выполняться правила:

- основной текст использует одну системную font stack без обязательной загрузки внешнего шрифта: `ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif`;
- базовый размер текста — `16 px`, базовая высота строки — `24 px`;
- шкала размеров содержит только `14`, `16`, `20`, `28`, `40 px` для текста, подписей и заголовков;
- высоты строк для этой шкалы равны соответственно `20`, `24`, `28`, `34`, `48 px`;
- начертания ограничены значениями `400`, `500`, `600`, `700`;
- заголовки, основной текст, подписи и кнопки визуально различимы по размеру или начертанию;
- длинные строки не превращаются в сплошную полосу: ширина текстового блока ограничена `720 px`;
- внешний шрифт не подключается из сети, если без сети страница теряет читаемость.

### 4.3. Отступы и вёрстка

- используется единая шкала отступов: `4`, `8`, `12`, `16`, `24`, `32`, `48`, `64 px`;
- все `margin`, `padding` и `gap`, кроме значения `0`, должны использовать значение этой шкалы;
- исключения разрешены только для `1 px` границ, размеров иконок и расчётов, необходимых для адаптивной сетки;
- основной контейнер имеет максимальную ширину `1120 px`;
- горизонтальные поля контейнера: `16 px` при ширине до `767 px`, `24 px` при ширине `768–1199 px`, `32 px` при ширине от `1200 px`;
- соседние секции и повторяющиеся карточки выровнены по общей сетке;
- при ширине `390 px` не возникает горизонтального скролла;
- изображения и медиа не выходят за ширину родительского контейнера.

### 4.4. Согласованность визуального стиля

Плагин должен привести повторяющиеся решения к общей системе:

- цвета вынесены в повторно используемые токены или переменные;
- используются отдельные токены для фона, поверхности, основного текста, вторичного текста, границы и акцентного цвета;
- один тип действия имеет одинаковые высоту, радиус, внутренние поля и состояние наведения во всех местах;
- радиусы элементов ограничены двумя значениями: `8 px` для контролов и `12 px` для крупных поверхностей;
- границы используют толщину `1 px`;
- одна и та же роль цвета не получает разные оттенки в соседних компонентах без зафиксированной причины;
- повторяющиеся компоненты не получают копии стилей с отличающимися отступами или радиусами;
- видимый `:focus`-стиль присутствует у клавиатурных интерактивных элементов;
- текстовый контраст составляет не менее `4.5:1`, крупный текст — не менее `3:1` относительно фона.

Плагин не должен стирать фирменный акцент страницы или заменять содержательные элементы декоративными заглушками. Он упорядочивает существующий визуальный язык, а не подменяет продукт другим дизайном.

## 5. Правила применения

1. До запуска зафиксировать исходные скриншоты и поведение интерактивных элементов.
2. Установить только один выбранный plugin package. Параллельная установка нескольких кандидатов запрещена: иначе нельзя доказать, какой пакет дал результат.
3. Запустить плагин с указанием `TARGET_PAGE` и требования сохранить контент и поведение.
4. Сначала получить аудит и план правок, затем разрешить внесение изменений.
5. Изменять только файлы, относящиеся к `TARGET_PAGE` и её стилям. Изменения конфигурации проекта, зависимостей и JS допустимы только при явном доказательстве, что без них страница не запускается; в отчёте указывается причина каждого такого изменения.
6. После правок повторно открыть страницу в браузере и выполнить проверки из раздела 10.
7. Сохранить скриншоты «до/после» с одинаковыми размерами окна, состоянием страницы и содержимым.
8. Зафиксировать diff и отдельно подтвердить, что изменения не затронули текст, URL ссылок и обработчики действий.

## 6. Критерии выбора и оценка кандидата

Каждому кандидату присваивается балл из `100`:

| Критерий | Баллы |
|---|---:|
| Действительно устанавливаемый plugin package с версией и источником | 20 |
| Не менее трёх связанных skills и описанный порядок их совместной работы | 20 |
| Аудит и улучшение существующей вёрстки | 15 |
| Системная типографика | 15 |
| Единая сетка и отступы | 15 |
| Согласованность цветов и повторяющихся компонентов | 15 |

Кандидат проходит отбор при результате не менее `80` баллов и при `0` балловых провалах в любой из четырёх обязательных областей. Если два кандидата проходят порог, выбирается кандидат с большей суммой за работу с существующей страницей; при равенстве — пакет с меньшим числом внешних зависимостей.

В отчёте для каждого проверенного кандидата указываются: название, источник, версия, состав skills, баллы по каждому критерию, причины отказа или причина выбора.

## 7. Состояния процесса

1. **Исходная страница:** страница открывается, скриншоты и поведение записаны.
2. **Поиск кандидатов:** собираются plugin packages; одиночные skills сразу помечаются как неподходящие.
3. **Проверка кандидата:** изучаются манифест, состав skills и инструкция применения; ставится оценка.
4. **Применение:** выбранный пакет сначала выполняет аудит, затем вносит согласованные изменения.
5. **Проверка результата:** страница открыта на двух ширинах, пройдены функциональные и визуальные проверки.
6. **Отклонение:** кандидат не устанавливается или изменения откатываются, если нарушена логика, не выполнен обязательный критерий либо визуальная проверка провалена.
7. **Принято:** выбранный пакет установлен, страница соответствует чек-листу, diff и доказательства сохранены.

## 8. Граничные случаи

- **Пустая секция или пустой список:** не удалять секцию и не подставлять выдуманный контент; сохранить предусмотренное страницей пустое состояние и выровнять его теми же отступами.
- **Длинный заголовок или слово без пробелов:** текст не должен вылезать за контейнер; разрешить перенос или безопасное усечение без горизонтального скролла.
- **Отсутствующее изображение:** сохранить место с соотношением сторон `16:9`, показать доступный alt-текст или нейтральный фон `#E5E7EB`; не ломать сетку.
- **Много повторяющихся карточек:** применить один набор правил ко всем карточкам; не исправлять только первую карточку вручную.
- **Первый и последний элемент списка:** внешние отступы не должны удваиваться из-за одновременных `margin` родителя и ребёнка.
- **Ширина `320 px`:** страница не имеет горизонтального скролла, кнопки и поля остаются доступными.
- **Ширина `390 px`:** проверить основной сценарий на мобильном экране.
- **Ширина `768 px`:** проверить переход между мобильной и широкой раскладкой.
- **Ширина `1440 px`:** проверить максимальную ширину контейнера и отсутствие растянутых на весь экран текстовых блоков.
- **Одновременные состояния:** элемент с `:hover` и `:focus` сохраняет читаемый текст и заметный контур; ошибка формы не скрывает фокус.
- **Повторный запуск:** второй запуск того же плагина не создаёт дубликаты CSS, повторные токены или новые уровни вложенности; визуальный результат остаётся тем же.
- **Уже аккуратная страница:** плагин обязан сохранить рабочие стили и выдать список проверенных критериев; массовая замена ради наличия diff запрещена.
- **Сломанный или неполный кандидат:** пакет не устанавливать; отсутствие манифеста, версии или инструкции считается причиной отказа.
- **Нет сети:** страница должна загрузиться с локальными ресурсами и системным шрифтом; внешний CDN не может быть единственной точкой отказа.
- **Неизвестный фреймворк или сборщик:** не переписывать проект на другую технологию; если пакет не умеет работать с текущим стеком, кандидат отклоняется.
- **Изменение логики:** при изменении текста, URL, обработчиков событий или состояния формы применение немедленно остановить и откатить.

## 9. Что не входит в задачу

- разработка нового сайта или нового макета с нуля;
- создание отдельного skill вместо поиска plugin package;
- установка и сравнение нескольких плагинов в одной рабочей копии;
- изменение бизнес-логики, API, данных, маршрутов и обработчиков JavaScript;
- смена фреймворка, сборщика, языка или архитектуры проекта;
- добавление авторизации, аналитики, платежей и серверной части;
- создание новых иллюстраций, логотипов и контентных блоков;
- подключение внешних шрифтов и библиотек только ради визуального эффекта;
- добавление анимаций, звука и игровых механик;
- оценка вкусовых предпочтений вместо проверки зафиксированных критериев.

## 10. Порядок выполнения

1. Определить `TARGET_PAGE` и убедиться, что она открывается в исходном проекте.
2. Снять два исходных скриншота: `1440×900` и `390×844`.
3. Проверить исходные ссылки, кнопки, поля и основной пользовательский сценарий.
4. Собрать кандидатов из разрешённого каталога по запросам, связанным с `web design`, `frontend`, `layout`, `typography`, `design system`.
5. Отсеять одиночные skills и пакеты без манифеста, версии или трёх связанных skills.
6. Изучить оставшиеся packages и заполнить таблицу оценки из раздела 6.
7. Установить одного победившего кандидата в отдельную рабочую копию или сохранить точку отката.
8. Запустить его аудит `TARGET_PAGE` и проверить, что план касается только визуальной доводки.
9. Применить правки в порядке: контейнеры и сетка → отступы → типографика → цветовые и компонентные токены → состояния и адаптивность.
10. Запустить страницу на ширинах `320`, `390`, `768` и `1440 px`.
11. Проверить интерактивные элементы мышью и клавиатурой, включая `Tab`, `Enter` и отправку формы, если форма существует.
12. Снять итоговые скриншоты `1440×900` и `390×844`, сравнить их с исходными.
13. Проверить diff, повторный запуск и отсутствие изменений в контенте и логике.
14. Сформировать отчёт и принять результат только при выполнении всех обязательных пунктов раздела 11.

## 11. Антипаттерны

- Называть одиночный `SKILL.md` плагином.
- Выбрать пакет по названию или рекламному описанию, не проверив состав и применение.
- Передавать плагину только фразу «сделай красиво» и не требовать её перевода в измеримые критерии до начала правок.
- Переписать страницу с нуля вместо точечной доводки существующей вёрстки.
- Исправить один компонент вручную, оставив его дубликаты в прежнем стиле.
- Добавить случайные значения `margin`, `padding`, `gap`, цвета и радиусы без общей шкалы.
- Менять текст, ссылки или JavaScript под предлогом визуального улучшения.
- Подключать внешние шрифты или библиотеку без необходимости и без проверки работы без сети.
- Проверить только ширину `1440 px` и объявить результат готовым.
- Считать доказательством фразу «стало лучше» без одинаковых скриншотов, diff и функциональной проверки.
- Запустить плагин повторно без проверки идемпотентности и получить дублированные стили.
- Оставить в отчёте несколько кандидатов вместо одного выбранного пакета и причины отказа остальных.

## 12. Критерии готовности

- [ ] `TARGET_PAGE` зафиксирована и открывается до начала применения.
- [ ] Если исходный запрос содержал слово `красиво`, плагин до правок преобразовал его в таблицу измеримых критериев из раздела 2 и зафиксировал эту интерпретацию в отчёте.
- [ ] Сохранены исходные скриншоты `1440×900` и `390×844`.
- [ ] Проверенный кандидат является plugin package, а не одиночным skill.
- [ ] Кандидат содержит не менее `3` связанных skills, манифест, версию и воспроизводимую инструкцию установки.
- [ ] Кандидат набрал не менее `80/100` и не провалил ни одну обязательную область.
- [ ] В отчёте указаны источник, версия, состав skills и причины выбора.
- [ ] Основной текст страницы использует заданную системную font stack, размер `16 px` и высоту строки `24 px`.
- [ ] Размеры текста находятся в шкале `14/16/20/28/40 px`, высоты строк — `20/24/28/34/48 px`.
- [ ] Отступы и интервалы используют шкалу `4/8/12/16/24/32/48/64 px` с указанными исключениями.
