# Browser Tetris Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a playable browser Tetris game in `tetris/index.html`, with a 10×20 board, seven colored tetrominoes, keyboard controls, line clearing, score, and `Game Over`.

**Architecture:** Keep the entire implementation in one self-contained HTML file as required by the assignment. Store settled cells in a 20-row × 10-column board array; represent the active tetromino as a matrix plus position; use canvas for rendering and a fixed game loop for gravity. Separate pure-ish collision/board operations from input, rendering, and loop orchestration so each gameplay rule can be inspected independently.

**Tech Stack:** Plain HTML, CSS, JavaScript, Canvas 2D API; no external dependencies.

**Spec:** `TZ_TETRIS.md`

## Global Constraints

- Create exactly one game page at `tetris/index.html`.
- Put HTML, CSS, and JavaScript inside that file.
- Use no external dependencies.
- Use a 10-cell-wide by 20-cell-high vertical playfield.
- Implement exactly the seven classic pieces `I`, `O`, `T`, `S`, `Z`, `J`, `L`, each with its own color.
- Support Left/Right movement, Up rotation by 90°, and Down accelerated falling.
- Clear completely filled horizontal lines and let cells above drop down.
- Show the score and award points for cleared lines.
- End the game with visible text `Game Over` when a newly spawned piece cannot fit.

### Task 1: Build the single-file game shell and board renderer

**Files:**
- Create: `tetris/index.html`

**Interfaces:**
- Produces the page structure (`canvas#game`, score element, game-over element) and JavaScript entry point for later gameplay tasks.
- Defines constants `COLS = 10`, `ROWS = 20`, `CELL_SIZE = 30` and a `draw()` function that renders the empty grid and any board/active-piece cells available at render time.

- [ ] **Step 1: Create the page shell**

Add a semantic page containing a heading, a `canvas` sized to `COLS * CELL_SIZE` by `ROWS * CELL_SIZE`, a score display initialized to `0`, and a hidden game-over message whose visible text is exactly `Game Over`. Include inline `<style>` and `<script>` blocks only; do not add external links or imports.

- [ ] **Step 2: Add the initial board state and renderer**

Inside the script, define:

```js
const COLS = 10;
const ROWS = 20;
const CELL_SIZE = 30;
const board = Array.from({ length: ROWS }, () => Array(COLS).fill(null));

function drawCell(x, y, color) {
  context.fillStyle = color;
  context.fillRect(x * CELL_SIZE, y * CELL_SIZE, CELL_SIZE, CELL_SIZE);
  context.strokeStyle = '#182338';
  context.strokeRect(x * CELL_SIZE, y * CELL_SIZE, CELL_SIZE, CELL_SIZE);
}

function draw() {
  context.clearRect(0, 0, canvas.width, canvas.height);
  context.fillStyle = '#0b1020';
  context.fillRect(0, 0, canvas.width, canvas.height);
  for (let y = 0; y < ROWS; y += 1) {
    for (let x = 0; x < COLS; x += 1) {
      if (board[y][x]) drawCell(x, y, board[y][x]);
      else {
        context.strokeStyle = '#182338';
        context.strokeRect(x * CELL_SIZE, y * CELL_SIZE, CELL_SIZE, CELL_SIZE);
      }
    }
  }
}
```

Wire `canvas` and its 2D context before the first call to `draw()`. Keep the score display and game-over element accessible by IDs.

### Task 2: Add tetromino definitions, spawning, movement, and rendering

**Files:**
- Modify: `tetris/index.html` (piece definitions and gameplay state/functions in the existing script)

**Interfaces:**
- Consumes: `board`, `drawCell()`, `draw()`, `COLS`, and `ROWS` from Task 1.
- Produces: `PIECES`, `player`, `createPiece(type)`, `spawnPiece()`, `collides()`, `merge()`, `rotateMatrix()`, `playerMove()`, `playerRotate()`, and an updated `draw()` that overlays the active piece.
- `player` has shape `{ pos: { x: number, y: number }, matrix: number[][], color: string, type: string }`.

- [ ] **Step 1: Define all seven pieces and colors**

Add a `PIECES` map with these matrices and distinct colors:

```js
const PIECES = {
  I: { matrix: [[1, 1, 1, 1]], color: '#38bdf8' },
  O: { matrix: [[1, 1], [1, 1]], color: '#facc15' },
  T: { matrix: [[0, 1, 0], [1, 1, 1]], color: '#c084fc' },
  S: { matrix: [[0, 1, 1], [1, 1, 0]], color: '#4ade80' },
  Z: { matrix: [[1, 1, 0], [0, 1, 1]], color: '#f87171' },
  J: { matrix: [[1, 0, 0], [1, 1, 1]], color: '#60a5fa' },
  L: { matrix: [[0, 0, 1], [1, 1, 1]], color: '#fb923c' }
};
```

Clone matrices when creating a piece so rotations never mutate the definitions.

- [ ] **Step 2: Implement spawning and collision detection**

Use a random key from `Object.keys(PIECES)`. Spawn at `y = 0` and horizontally center the matrix with `x = Math.floor((COLS - matrix[0].length) / 2)`. Implement `collides(piece)` by rejecting cells outside the board or overlapping a non-null `board` cell. Start the game with `spawnPiece()`.

- [ ] **Step 3: Implement movement and rotation**

Implement `playerMove(offset)` by changing `player.pos.x` only when the candidate does not collide. Implement clockwise `rotateMatrix(matrix)` and `playerRotate()` by applying the candidate matrix, reverting it if it collides; if a rotation touches a wall, try shifting one cell away from the wall before reverting.

- [ ] **Step 4: Overlay the active piece in `draw()`**

Keep settled cells rendered first, then draw every active matrix cell whose value is truthy at `player.pos.x + x`, `player.pos.y + y` using `player.color`. Ensure an active piece never creates a canvas coordinate outside the board during normal play.

- [ ] **Step 5: Verify movement and rotation manually**

Open the page and confirm each of the seven pieces can appear, `ArrowLeft` and `ArrowRight` move the active piece but not through walls, and `ArrowUp` rotates it without disappearing or overlapping settled cells.

### Task 3: Add gravity, locking, line clearing, scoring, and game over

**Files:**
- Modify: `tetris/index.html` (loop, locking, line clearing, scoring, and game-over behavior)

**Interfaces:**
- Consumes: `player`, `spawnPiece()`, `collides()`, `draw()`, `board`, `ROWS`, `COLS` from Tasks 1–2.
- Produces: `playerDrop()`, `merge()`, `clearLines()`, `updateScore()`, `gameOver`, and the complete playable game loop.

- [ ] **Step 1: Implement locking and line clearing**

Implement `merge()` to copy each truthy active matrix cell into its corresponding board cell. Implement `clearLines()` by scanning from the bottom upward; when a row has no null cells, remove it, prepend a null-filled row, increment a local line count, and recheck the same index. Return the number of cleared lines.

- [ ] **Step 2: Implement score updates**

Track `score = 0` and update the visible score after every lock. Award points according to the number of lines cleared in one lock: 1 line = 100, 2 = 300, 3 = 500, 4 = 800. The display must remain numeric and visible beside the field.

- [ ] **Step 3: Implement drop and spawn/game-over transition**

Implement `playerDrop()` by trying to increment `player.pos.y`. If the candidate collides, decrement `y`, merge the piece, clear lines, update the score, spawn the next piece, and set `gameOver = true` plus reveal the game-over element if the newly spawned piece collides immediately. Do not schedule further drops after game over.

- [ ] **Step 4: Add gravity and keyboard handling**

Use a `dropCounter`, `dropInterval` (for example `800` milliseconds), and `requestAnimationFrame(update)` to call `playerDrop()` at the interval and redraw every frame. Add a `keydown` listener for `ArrowLeft`, `ArrowRight`, `ArrowUp`, and `ArrowDown`; prevent default scrolling for these keys, move/rotate for the first three, and call `playerDrop()` for `ArrowDown`. Ignore input after `gameOver`.

- [ ] **Step 5: Verify complete gameplay manually**

Open the page and check:

- pieces fall automatically from the top;
- Down accelerates a piece;
- a piece locks on the floor or another piece;
- the next piece appears at the top center;
- completed rows disappear and blocks above fall down;
- the score increases for one or more cleared rows;
- filling the spawn area eventually reveals exactly `Game Over` and stops gameplay.

- [ ] **Step 6: Commit the complete game**

```bash
git add tetris/index.html
git commit -m "feat: complete playable tetris game"
```
