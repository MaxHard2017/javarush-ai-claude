# Техническое задание: «Эволюция» для плиток 2048

## 1. Суть задачи

В существующей игре 2048 необходимо заменить числовую надпись внутри игровой плитки на эмодзи, обозначающие последовательные ступени эволюции. Числовое значение плитки должно остаться внутренним значением игры: оно продолжает участвовать в движении, проверке одинаковых плиток, слиянии, подсчёте очков, победе и проигрыше.

Меняется только визуальное представление плитки. Технологический стек не меняется: существующий `index.html`, ванильный JavaScript и CSS без сторонних библиотек.

## 2. Границы изменения

### Разрешено менять

1. Функцию, которая преобразует числовое значение плитки в отображаемый текст.
2. Таблицу соответствия «числовое значение → эмодзи эволюции».
3. CSS-правило размера содержимого плитки, если это нужно для размещения эмодзи внутри ячейки.
4. Комментарии, описывающие новый визуальный слой.

### Запрещено менять

1. Размер игрового поля `4 × 4`.
2. Числовое хранение значений плиток и массив `grid`.
3. Начальное появление двух плиток.
4. Вероятность появления новой плитки: `90%` для значения `2` и `10%` для значения `4`.
5. Перемещение плиток влево, вправо, вверх и вниз.
6. Слияние только двух одинаковых соседних плиток за один шаг.
7. Запрет повторного слияния уже объединившейся плитки в том же ходу.
8. Добавление ровно одной новой плитки после результативного хода.
9. Отсутствие новой плитки после хода, который не изменил поле.
10. Подсчёт очков.
11. Условие победы: максимальное числовое значение на поле не меньше `2048`.
12. Условие проигрыша: на поле нет пустых ячеек и нет пары соседних плиток с одинаковым значением.
13. Управление стрелками, клавишами `WASD` и свайпами.
14. Звуки, кнопку новой игры, кнопку выключения звука и экранные оверлеи.
15. Существующие цвета плиток, длительность анимаций движения и анимации `pop`/`pulse`, кроме точечной настройки размера эмодзи.

## 3. Таблица эволюции

Для каждого значения из таблицы отображается строго указанное эмодзи. Число в первом столбце не показывается внутри плитки.

| Числовое значение плитки | Эмодзи | Название ступени |
|---:|:---:|---|
| `2` | `🦠` | амёба |
| `4` | `🐟` | рыба |
| `8` | `🦎` | ящер |
| `16` | `🐒` | примат |
| `32` | `🧑` | человек |
| `64` | `🧑‍🔬` | учёный |
| `128` | `🧑‍🚀` | космонавт |
| `256` | `🤖` | робот |
| `512` | `🦾` | киборг |
| `1024` | `👽` | инопланетянин |
| `2048` | `🪐` | планета |
| `4096` | `🌌` | галактика |
| `8192` | `🌠` | звёздная система |
| `16384` | `✨` | сверхновая |
| `32768` | `♾️` | бесконечность |
| `65536` | `🌀` | сингулярность |

В таблице предусмотрено `16` ступеней, поэтому цепочка покрывает значения от `2` до `65536`, включая `2048`, `4096` и более высокие значения.

### Значения выше `65536`

Для любого числового значения больше `65536` отображается `🌀`, соответствующее последней ступени таблицы. Числовое значение при этом не ограничивается и не заменяется: плитка продолжает хранить фактическое число и может участвовать в дальнейших слияниях.

## 4. Правила отображения

1. Функция отображения принимает числовое значение плитки и возвращает строку с эмодзи.
2. Для значений `2`, `4`, `8`, `16`, `32`, `64`, `128`, `256`, `512`, `1024`, `2048`, `4096`, `8192`, `16384`, `32768` и `65536` возвращается значение из таблицы эволюции.
3. Для значения больше `65536` возвращается `🌀`.
4. Для значения `0` функция возвращает пустую строку. Пустые ячейки не имеют DOM-плитки и не показывают эмодзи.
5. Для любого другого значения, которое не является положительной степенью двойки, функция возвращает `🦠` как безопасное отображение стартовой ступени; числовая логика при этом не изменяется.
6. Число не должно добавляться рядом с эмодзи, под ним или вместо него.
7. Значение `data-value` DOM-элемента должно оставаться числом, чтобы существующая функция позиционирования продолжала работать.
8. После слияния числовое значение выжившей плитки удваивается по существующему правилу, затем её отображение обновляется на эмодзи следующей ступени.
9. Удаляемая при слиянии плитка не должна получать отдельную новую ступень после удаления.
10. Новая плитка после хода должна показывать `🦠` для числового значения `2` или `🐟` для числового значения `4`.
11. Обозначение ступени должно помещаться внутри квадратной ячейки и не перекрывать соседние плитки.
12. Размер эмодзи задаётся относительно размера ячейки: базовый размер — `50%` от стороны ячейки; для составных эмодзи `🧑‍🔬`, `🧑‍🚀` и `♾️` применяется размер `38%` от стороны ячейки.
13. Эмодзи выравнивается по горизонтали и вертикали по центру плитки.
14. Перенос строки внутри эмодзи запрещён.
15. Эмодзи не должны менять размеры плитки, положение плитки, отступы сетки или геометрию поля.

## 5. Игровая механика, которую нужно сохранить без изменений

### Ход

1. Игрок задаёт направление стрелкой, клавишей `WASD` или свайпом.
2. Все плитки сдвигаются в указанную сторону по текущим правилам.
3. Две соседние плитки с одинаковым **числовым** значением сливаются в одну.
4. При слиянии значение новой плитки равно сумме двух исходных значений, то есть удваивается.
5. Внешний вид результата определяется новым числовым значением через таблицу эволюции.
6. После результативного хода добавляется ровно одна новая плитка.
7. После нерезультативного хода новая плитка не добавляется.
8. Во время текущей анимации новый ход игнорируется, как и до изменения темы.

### Очки и победа

1. За слияние к счёту добавляется новое числовое значение объединённой плитки.
2. В полях `Score` и `Best` показываются числа, а не эмодзи.
3. Победа наступает при `maxValue() >= 2048`.
4. При достижении числового значения `2048` плитка показывает `🪐`.
5. После достижения победы игрок может продолжить игру; дальнейшие слияния не блокируются.

### Проигрыш

1. Проигрыш определяется только функцией проверки доступных ходов.
2. Если свободных ячеек нет и одинаковых соседних числовых значений нет, показывается существующий экран проигрыша.
3. Эмодзи не участвуют в сравнении плиток и не влияют на определение проигрыша.

## 6. Граничные случаи

1. **Пустое поле:** пустая ячейка не создаёт DOM-элемент плитки и не отображает эмодзи.
2. **Начальная партия:** создаются две плитки; каждая показывает `🦠` при значении `2` или `🐟` при значении `4`.
3. **Плитка у края поля:** эмодзи остаётся по центру плитки; координаты, размеры и направление движения не меняются.
4. **Два одинаковых значения:** сравниваются числа, а не строки эмодзи. Две плитки `🦠` с числовым значением `2` сливаются в `🐟` со значением `4`.
5. **Цепочка из четырёх одинаковых плиток:** применяется действующее правило одного слияния на плитку за ход; нельзя получить два слияния одной и той же плитки в одном ходу.
6. **Два слияния за один ход:** каждое слияние обновляет внешний вид своей выжившей плитки независимо от другого слияния.
7. **Слияние во время анимации:** повторный ввод игнорируется; нельзя создать дополнительное слияние или новую плитку.
8. **Значение `2048`:** отображается `🪐`, показывается существующий экран победы, игровая механика не меняется.
9. **Значение `4096` и выше:** число продолжает удваиваться по правилам игры, а отображение выбирается по таблице или правилу для значений выше `65536`.
10. **Значение выше последней ступени:** отображается `🌀`; плитка не становится числом и не исчезает.
11. **Нераспознанное положительное значение:** отображается стартовое `🦠`; значение не изменяется и не сбрасывается.
12. **Изменение размера окна:** эмодзи и плитка пересчитывают размер вместе с ячейкой; положение на поле остаётся тем же.
13. **Мобильный экран:** поле сохраняет квадратную форму и помещается в доступную ширину; эмодзи не выходят за пределы плитки.
14. **Одинаковый внешний вид при разных значениях:** если два значения попали в один fallback-вид, это не меняет их числовое сравнение и доступность слияния.

## 7. Управление и ввод

Существующие способы управления сохраняются без изменений:

- `ArrowLeft` или `A` — движение влево;
- `ArrowUp` или `W` — движение вверх;
- `ArrowRight` или `D` — движение вправо;
- `ArrowDown` или `S` — движение вниз;
- свайп по доске длиной не менее `30` пикселей — движение в направлении свайпа.

Ввод, который не соответствует направлению, короткий свайп длиной менее `30` пикселей и любой ввод во время анимации длительностью `120` миллисекунд не должен менять состояние игры.

## 8. Визуальные требования

1. Фон страницы, фон доски, пустые ячейки, цвета текста и существующая палитра плиток сохраняются.
2. Радиус скругления плитки сохраняется равным `6px`.
3. Отступ доски и расстояние между ячейками сохраняются равными значению CSS-переменной `--gap`, то есть `12px`.
4. Эмодзи отображаются внутри существующего элемента `.face`.
5. `.face` сохраняет `display: flex`, горизонтальное и вертикальное центрирование, ширину `100%` и высоту `100%`.
6. Запрещено подключать внешние шрифты, изображения, SVG-наборы или библиотеки эмодзи.
7. Используется системный способ отображения Unicode-эмодзи браузером.
8. Анимация появления новой плитки и пульса после слияния сохраняется.
9. Текст подсказки, заголовок игры, подписи `Score` и `Best` и текст оверлеев не переводятся на эмодзи.

## 9. Состояния экрана

### Начало игры

- отображается доска `4 × 4`;
- на доске находятся две стартовые плитки `🦠` или `🐟` в зависимости от выпавшего значения;
- счёт равен `0`;
- отображаются существующие кнопки `Новая игра` и звука.

### Игра продолжается

- каждая занятая ячейка показывает эмодзи по числовому значению своей плитки;
- счёт и лучший результат показываются числами;
- игрок может использовать все существующие способы управления.

### Победа

- при первом достижении значения `2048` отображается `🪐`;
- показывается существующий оверлей победы;
- кнопки `Продолжить` и `Новая игра` работают как прежде;
- при продолжении слияния значений выше `2048` разрешены.

### Проигрыш

- показывается существующий оверлей проигрыша;
- счёт остаётся числом;
- кнопка `Заново` запускает новую игру с двумя стартовыми плитками;
- внешний вид плиток в новой партии снова начинается со ступеней `🦠` и `🐟`.

### Изменение размера окна

- доска сохраняет квадратную форму;
- плитки остаются на своих координатах;
- размер эмодзи пересчитывается вместе с размером плитки;
- состояние игры и числовые значения не меняются.

## 10. Что не входит в задачу

В этой задаче не нужно:

1. Переписывать алгоритм 2048.
2. Менять размер поля.
3. Менять правила слияния или порядок движения.
4. Добавлять новые режимы игры, уровни сложности или таблицу лидеров.
5. Добавлять новые звуки, музыку или частицы.
6. Менять порог победы `2048`.
7. Заменять числа в счёте и лучшем результате на эмодзи.
8. Добавлять подписи с названиями животных и существ под эмодзи.
9. Добавлять отдельный экран или меню выбора темы.
10. Подключать сторонние библиотеки, изображения или внешние сервисы.
11. Менять сохранение лучшего результата и настройки звука в `localStorage`.
12. Исправлять несвязанные с визуальным отображением дефекты.

## 11. Порядок выполнения

1. Сохранить резервную точку текущего рабочего файла перед изменениями.
2. Создать неизменяемую таблицу соответствия чисел и эмодзи из раздела 3.
3. Изменить только функцию получения отображаемого содержимого плитки.
4. Добавить fallback для значений выше `65536` и для нераспознанных значений согласно разделу 4.
5. Проверить, что DOM-элемент продолжает хранить числовое значение в `data-value`.
6. Настроить размер эмодзи без изменения размеров плитки и сетки.
7. Проверить обновление внешнего вида после слияния.
8. Проверить появление новой стартовой плитки после результативного хода.
9. Проверить победу, продолжение после победы и проигрыш.
10. Проверить изменение размера окна на широком и мобильном размере.
11. Не менять код движения, слияния, генерации плиток, очков и проверки окончания игры.

## 12. Анти-паттерны

1. Не заменять числовые значения плиток строками эмодзи в `grid`.
2. Не сравнивать плитки по тексту DOM-элемента вместо числового значения.
3. Не удалять числа из `data-value`.
4. Не добавлять отдельную механику для каждой ступени эволюции.
5. Не дублировать алгоритм слияния ради смены отображения.
6. Не показывать одновременно число и эмодзи внутри плитки.
7. Не использовать длину строки эмодзи как игровое значение.
8. Не менять порог победы из-за того, что `2048` теперь выглядит как `🌌`.
9. Не считать плитки одинаковыми только потому, что у них одинаковый fallback-внешний вид.
10. Не добавлять новую плитку после нерезультативного хода.
11. Не разрешать повторный ввод, пока предыдущий ход анимируется.
12. Не подключать библиотеку ради простой таблицы соответствий.
13. Не менять цвета и анимации, если для этого нет требования раздела 8.
14. Не использовать изображения или внешние URL вместо Unicode-эмодзи.
